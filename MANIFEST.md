# What a member is, as files

`python3 tribe.py validate` is the authority. This file explains it; the code enforces it.

A member is a directory under `wake/members/<name>/` holding a `state/` and an `output/`. Nothing else
about a member is stored anywhere — not in the harness, not in a database, not in a model. **If a file is
missing, the member is not smaller; it is broken**, and until 2026-11-02 it broke silently at its first wake
with a model improvising around the hole.

| file | who writes it | what it is for |
|---|---|---|
| `state/identity.md` | member | who it is: name, seat, and the rule it holds itself to. Must name itself `member <name>`. |
| `state/state.md` | harness | what it currently thinks. Exactly three lines are machinery: `Wakes so far:`, `Last wake:`, `Model used:` — the harness increments and stamps them. Edit the prose, never those three lines. |
| `state/open-items.md` | member | numbered things it is trying to do. **Numbers must be unique** — the harness acts on one item per wake and takes the first match. |
| `state/journal.md` | harness + member | what it did at each wake. Appended, never rewritten. It is read back into the prompt as the member's own memory; a record the member cannot see is not a memory. |
| `state/voice.md` | human | `api:` and `model:` — the model it borrows. Changing this does not make it someone else. |
| `state/requests.md` | member | read-only checks it wants run before its next wake (five at most, `ls`/`wc`/`sha256sum`/`shasum`/`date`/`git log|show|diff`). |
| `state/findings.md` | harness | what those checks said. Consumed requests are cleared. |
| `state/brief.md` | **generated by `brief.py`** from the files below | what the tribe is working on now: what closes soonest, what is waiting on this member, what is queued, with every interval computed from the real date. **Included in the prompt.** Hand-editing it is pointless: it is regenerated before every wake, because a typed summary can disagree with the files it summarises (measured 2026-11-02, `lab/results/RESULTS-R15.md`). A structure the harness does not hand over does not exist to the member — measured 2026-11-02, see `lab/results/RESULTS-R13.md`. |
| `output/` | member | its acts: one markdown file per wake, plus the raw reply for the record. |

## Making one

```
python3 tribe.py new d --seat "the archivist" --api gemini --model gemini-3.8-flash
python3 tribe.py validate d
./talk.sh d "read your identity and say what you are for"
```

`new` refuses to overwrite an existing member directory. That is deliberate: the mistake it prevents is
running it twice and destroying a record, which is the one mistake in this repository that cannot be undone
by reading the diff.

## What is not in the schema, and should be

- No version field. A member created by an older layout is not distinguishable from a broken one.
- No size limit on the journal. It is truncated to the last 4,000 characters in the prompt, so a long
  journal silently becomes a short memory — which is a design decision, but nothing states it in the file.
- No check that `open-items.md` has anything to act on, only that its numbers are unique.
